# Internationalization verification

Verified locally on 2026-11-09 against production builds of Auth, Console, Studio,
and Web, using `en-us`, `en-in`, and `es-es`.

## Automated results

| Check                                  | Result                                                                    |
| -------------------------------------- | ------------------------------------------------------------------------- |
| `pnpm check`                           | Pass: formatting, lint (incl. `check:i18n`), and all workspace typechecks |
| `pnpm check:ci`                        | Pass without writing files                                                |
| `pnpm build`                           | All four Next.js apps build successfully                                  |
| Frozen/offline dependency installation | Pass                                                                      |
| `git diff --check`                     | Pass                                                                      |

## Browser results

- All four apps render in every supported locale with the correct `html lang`,
  `dir`, titles, and translated page headings.
- Both locale selectors work. Combobox filtering and its no-results state work.
  Returning to `/` restores the selected locale from the locale cookie.
- Switching locales preserves account paths, query parameters, and URL fragments.
- The existing signed-in session can navigate Profile, Security, Sessions, and
  Activity. Session dates differ appropriately between US English, Indian English,
  and Spanish. Shared navigation, filters, pagination, and empty states translate.
- An empty profile name displays the Spanish validation message. Cancelling
  restores the form without saving account changes.
- Auth redirects an already signed-in visitor to the allowed Studio origin,
  preserving the requested target locale and query string. Local production
  processes receive explicit `STUDIO_APP_URL` and `CONSOLE_APP_URL` values to
  represent the local multi-port topology.
- The final browser console review reports no warnings or errors in any app.

Browser testing found and fixed the locale selector's lost query/fragment, its
incorrect empty state, untranslated avatar/notification labels, and inconsistent
Spanish Studio/Console headings. Production builds also exposed and resolved
`next-intl` aliases bypassing server exports and translations accessing request
state without an explicit route locale during static prerendering.

## Boundaries

OAuth handshakes, uploads, session revocation, history deletion, and location
permission changes were not executed. No account data was saved or deleted.
Native operating-system file-dialog text follows the browser/OS language.

The account schema persists regional preferences (including IANA time zone and
date/time/number choices). Server request config and first client paint still use
the stable `UTC` fallback and static `i18nFormats`; Auth account routes apply saved
values client-side via `AuthAccountFormatProvider` after load. Other apps remain on
the root `I18nProvider` only.

Screenshot capture was unavailable in the browser tool. Browser verification used
live pages, accessibility/DOM observations, and browser console logs.
