# Auth application — page action list

Review date: 2026-11-14. Scope: every `page.tsx` in `apps/auth/src/app`, including Account and Organizations. URLs use `en-us`; `en-in` and `es-es` use the same paths. `/auth` is the app base path. Query parameters are shown only where they change the workflow. API endpoints and route error/loading boundaries are not separate pages.

**How to read:** Each ID below is a **report ID**, assigned for tracking; it is not necessarily an ID registered in the application. `Now` means code for the action exists, not that it was tested end to end. `Proposed` means a possible or needed action, not an approved product requirement. Scores are rough review estimates out of 100, not test results or a security certification. They consider the screen's purpose, expected success and failure cases, usability, permissions, and evidence available. A zero means the proposed action is not available on the screen. Shared controls are listed once below and apply where that shell is shown. This is a first code-based inventory; browser behavior, provider setup, database migrations, and full role tests were not verified in this review. The current working tree contains in-progress Phase 9 changes, so scores may change.

**Cross-cutting destructive UX (item 105, 2026-11-14):** Account deletion, session revoke (one / other), provider unlink, location disable/delete, activity clear/delete, and invitation **decline** use `AlertDialog` confirmation, disable primary/cancel while in flight, and block dismiss via `onOpenChange` until the mutation finishes (`tests/auth-destructive-action-guards.test.ts`, plus focused UI tests below). **Not in scope:** org **leave** (deferred — [org-roles-rbac.md](./requirements/org-roles-rbac.md)); device OAuth approve/deny (pending buttons only, no second-step confirm); global sign-out from the account menu (immediate). Live browser pass for every surface still open.

**Cross-cutting overlay focus (item 109, 2026-11-14):** Base UI dialog/sheet primitives support `finalFocus`; controlled opens use `useOverlayReturnFocus` (`@packages/ui/hooks/use-overlay-return-focus`) on the account command palette and mobile sidebar sheet; confirm/sheet/dialog return-focus regression in `tests/ui-dialog-keyboard-focus.test.tsx`. Module confirm dialogs should call `captureReturnFocus` before `setOpen(true)` when not using `*Trigger` (pattern not audited on every screen).

**Cross-cutting mutation retry (item 106, 2026-11-14):** Transient outages retry on **reads** (`withClientRetry`, `callSecurityRpc` / billing / storage helpers) and **idempotent writes** (`invokeIdempotentSecurityMutation` on `activity.clear`; Better Auth session/profile mutations via `runAuthMutation`). **Preference forms** and **location history delete** rely on **manual resubmit** (no client auto-replay — avoids duplicate activity/audit rows). **Ambiguous provider unlink** reconciles via account list refresh instead of a second unlink when the row is already gone (`connected-accounts.hook.unlink`). **Guards:** mutation `isPending` / local `busy`; cache invalidation only on `status: "success"` (`tests/activity-mutation-cache.test.tsx`, `tests/location-mutation-cache.test.tsx`, `tests/sessions-revoke-cache.test.tsx`); avatar preview rolls back when `afterUpload` / `afterClear` reject. **Tests:** `tests/account-mutation-retry.test.tsx`, `tests/security-rpc-client.test.ts`. **Remaining:** live double-submit on slow networks; location delete after lost success still needs manual confirm.
