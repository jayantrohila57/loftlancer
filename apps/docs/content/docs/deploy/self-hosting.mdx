Production runs as **one Vercel project** (path routing in `vercel.json`) and **Neon** PostgreSQL. The canonical runbook is [`docs/database.md`](https://github.com/jayantrohila57/loftlancer/blob/main/docs/database.md).

## Apps to deploy

| App | Purpose |
| --- | --- |
| `apps/docs` | Landing, pricing and docs, served at `/` |
| `apps/auth` | Authentication + OAuth, served at `/auth` |
| `apps/studio` | Studio dashboard, served at `/studio` |

Set platform URLs (`NEXT_PUBLIC_AUTH_URL`, `NEXT_PUBLIC_STUDIO_URL`, `NEXT_PUBLIC_DOCS_URL`, `NEXT_PUBLIC_MCP_URL`) so CTAs and SSO redirects resolve correctly.

## Database

Apply schema with `pnpm db:push` against your Neon branch. Major migrations may ship as reviewed SQL under `packages/drizzle/src/migrations/`.

## Feature flags

Pair server flags with `NEXT_PUBLIC_*` mirrors and redeploy after changes (values are inlined at `next build`). See the production deploy checklist for organizations, notifications, variables v2, audit, and soft deletes.

## Local build verification

```bash
pnpm install
pnpm check-types
pnpm build
```

## Destructive seed

`pnpm db:reset-seed` is documented in `docs/database.md` and requires explicit confirmation — do not run against production without a backup branch.
