<Callout type="warn">
The MCP server is built (`@loftlancer/mcp`) but **not deployed** on loftlancer.com right now: `/api/mcp` returns 404. OAuth consent and device sign-in in the auth app work; the tool endpoint does not. These pages describe how it works once hosted.
</Callout>


The MCP HTTP stack uses **`@loftlancer/mcp`** (SDK auth/CORS/rate-limit) plus **`@loftlancer/orpc/mcp`** (`registerMcpTools` / `createLoftlancerMcpHttpHandler`). Each tool maps to a canonical action implemented in **`@loftlancer/orpc/mcp`**.

**End users:** start with [Using MCP](/docs/mcp/usage) and [Connect MCP clients](/docs/mcp/connecting-clients).

## Endpoints

Configure your client with:

- **Auth issuer** — `NEXT_PUBLIC_AUTH_URL` (default `https://loftlancer.com/better-auth`)
- **MCP URL** — `NEXT_PUBLIC_MCP_URL` (deployment-specific)

Tokens must include the base scope **`mcp:tools`** plus resource scopes listed on each tool page. The auth app advertises scopes from `MCP_OAUTH_SCOPES` in `@loftlancer/actions`.

## Tool discovery

Call the built-in **`permissions_snapshot`** tool (requires only `mcp:tools`) to list exposed actions, tool names, required scopes, and descriptions — same data as the [tool index](/docs/mcp/tools).

## Rate limits

`@loftlancer/mcp` applies per-user and per-client rate limits (`utils/mcp.rate-limit.ts`). Write and reveal verbs use stricter limits than reads.

## Authorization

Scopes gate whether a tool may be invoked; **`requireAction`** still enforces org role and project grants on the server. A token with `projects:write` cannot bypass missing org membership.
